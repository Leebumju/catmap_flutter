# 봤냥 Flutter 이식

iOS 앱(Swift / SwiftUI / TCA)을 Flutter(bloc)로 옮기는 중이다.
기준은 출시된 버전(main, v1.1.0)이고, 지금까지 **피드 · 로그인 · 지도 · 사진 등록**을 옮겼다.

**서버는 한 줄도 안 바꿨다.** iOS 앱이 쓰는 것과 같은 Supabase RPC
(`get_sightings_feed_v3`, `get_sightings_with_like_status_v2`, `get_my_sighting_count`,
`toggle_like`, `toggle_confirmation`)를 그대로 호출한다. 바뀐 건 부르는 언어뿐이다.

## 옮긴 기능

**피드**
- 커서 페이징 (created_at + id 복합 커서, 15개씩)
- 세로 페이저 = 다음 목격 기록 / 가로 페이저 = 같은 기록의 다음 사진
- 좋아요, "저도 봤어요" 토글
- 신고 (사유 4종), 유저 차단, 본인 게시물 삭제
- 비로그인 / 정지 계정 분기

**로그인**
- 카카오 로그인 (Supabase OAuth, `catmap://login-callback` 으로 복귀)
- 첫 로그인 시 users 행 생성 + 닉네임 자동 생성(중복이면 숫자 붙여 재시도)
- "최근 로그인" 표시

**지도**
- 반경 5km 목격 기록 조회, 같은 자리 마커는 원형으로 흩어 배치
- 200m 이상 움직이면 "이 위치에서 검색" 버튼, 조회는 2초 쓰로틀
- 주소·장소 검색, 내 위치 버튼, 마커 팝업

**사진 등록**
- 카메라 촬영 / 갤러리 선택 (최대 3장)
- 정사각형 자르기 (끌기·확대, 3분할 안내선, 건너뛰기)
- 메모 100자, 길냥이/집냥이, 위치 조정(지도에서 직접 선택)
- 사진 EXIF 촬영 위치 자동 반영
- 업로드 게이트: 로그인 → 정지 계정 → 게시물 30개 제한 → 최초 1회 안내

## 구조

```
lib/
├── domain/            # 모델 + 저장소 인터페이스. Flutter·Supabase 를 모른다
├── data/              # Supabase / geolocator / 카카오 로컬 구현. 바깥 SDK 는 여기까지만
└── features/
    ├── app/           # 탭 껍데기 + 전역 로그인 상태(SessionBloc)
    ├── auth/          # 로그인 화면
    ├── feed/          # 목격 피드
    ├── map/           # 지도, 주소 검색
    └── upload/        # 촬영 → 자르기 → 작성 → 등록
```

원본 앱의 계층(Domain / Core / Feature)을 그대로 옮겼다. 데이터 접근이 인터페이스
뒤에 있어서 테스트에서 가짜 구현으로 갈아끼울 수 있다.

## TCA 로 짰던 것과 뭐가 달랐나

옮기면서 실제로 걸렸던 것들.

**1. 중복 요청을 막는 자리가 다르다.**
TCA 는 리듀서 안에서 `guard !state.isTogglingLike` 로 막았다. bloc 은 그걸 event
transformer 로도 선언할 수 있다 — `on<Event>(handler, transformer: droppable())`.
페이저 스크롤 콜백이 초당 여러 번 튀는데, 없으면 같은 페이지를 중복으로 받는다.
상태 플래그로도 되지만 transformer 쪽이 의도가 드러난다. 둘 다 남겨뒀다.

**2. 일회성 신호를 담을 자리가 없다.**
TCA 는 `delegate` 액션으로 부모에게 "로그인 필요" 를 한 번 던졌다. bloc 은 상태만
흘려보내서, 그냥 상태에 넣으면 리빌드마다 스낵바가 다시 뜬다. `signal` 필드를 두고
화면이 처리한 뒤 지우는 방식으로 풀었다 (`listenWhen` 으로 값이 바뀐 순간만 듣는다).

**3. 수명을 직접 챙겨야 한다.**
TCA 는 전역 스토어에 리듀서를 합성해 트리를 만든다. bloc 은 화면 단위 인스턴스라
`BuildContext` 에 매달려 살고, PageController 같은 건 `dispose()` 에서 직접 푼다.

**4. 시간 타입이 조용히 위험하다.**
`created_at` 이 timestamptz 라 오프셋이 붙어 온다. 커서 페이징이 이 값으로 이어지기
때문에 UTC 로 안 맞추면 페이지 경계에서 글이 빠지거나 겹친다. 모델 변환에서 `.toUtc()` 로
고정하고 테스트로 박아뒀다. Swift `Date` 는 그 자체가 절대시각이라 신경 안 쓰던 부분이다.

**5. Dart enum 에는 raw value 가 없다.**
Swift 의 `enum CatType: String` 은 서버 문자열과 바로 매핑됐다. Dart 는 필드로 들고
`fromRawValue` 를 따로 둬야 한다. 모르는 값은 기본값으로 떨어뜨려서, 서버가 종류를
늘려도 구버전이 안 깨지게 했다.

**6. bigint 는 int 로 안 온다.**
`like_count` 가 bigint 라 Dart 쪽에 `num` 으로 도착한다. `as int` 로 캐스팅하면
런타임에 터진다. `(row['like_count'] as num?)?.toInt()` 로 받는다.

## iOS 와 달라진 것

애플 전용 기능이라 그대로 옮길 수 없었던 것들이다. 임의로 바꾼 게 아니라
안드로이드에 같은 게 없어서 다른 길로 간 자리다.

| 무엇 | iOS | 안드로이드 | 영향 |
|------|-----|-----------|------|
| 지도 | MapKit | OpenStreetMap (flutter_map) | 국내 지도 상세도가 떨어진다 |
| 장소 검색 | MKLocalSearch | 카카오 로컬 API | `KAKAO_REST_API_KEY` 가 필요하다 |
| 좌표 → 주소 | CLGeocoder | 안드로이드 Geocoder | 동 단위까지 쓰는 건 같다 |
| 애플 로그인 | 네이티브 | **없음** | 애플로 가입한 사람은 안드로이드에서 못 들어온다 |
| 최근 로그인 저장 | 키체인 | SharedPreferences | 앱을 지우면 표시가 사라진다 |

**로그인이 끝나는 자리가 다르다.** iOS 는 `signIn` 이 세션을 바로 돌려주지만,
안드로이드는 브라우저로 나갔다가 딥링크로 돌아온다. 그래서 로그인 성공은 로그인
화면이 아니라 세션 스트림(`SessionBloc`)이 받는다. 로그인 창을 띄운 뒤 화면을 로딩
상태로 잡아두지 않는 이유도 이것이다 — 사용자가 브라우저를 그냥 닫고 돌아올 수 있고,
그때 로딩이 남아 있으면 화면이 굳는다.

**OpenStreetMap 타일은 공개 서버를 쓴다.** 무료지만 대량 사용을 금지하는
[타일 사용 정책](https://operations.osmfoundation.org/policies/tiles/)이 있다.
사용자가 늘면 타일 서버를 따로 두거나 상용 지도로 옮겨야 한다.

**게시물 개수를 못 셀 때 iOS 는 아무 일도 일어나지 않는다.** (오류를 삼키고 카메라가
안 열린다.) 여기서는 "잠시 후 다시 시도해주세요" 를 띄운다 — 사용자가 버튼이 고장난
줄 알게 두지 않으려고 남긴 차이다.

## 옮기면서 지킨 원본 동작

포팅은 동작을 바꾸지 않는 게 원칙이라, 아래는 "더 나아 보여도" 그대로 뒀다.

- **좋아요를 낙관적으로 처리하지 않는다.** 서버가 돌려준 토글 결과로만 상태를 바꾼다.
  반응이 반 박자 늦지만 좋아요 수가 서버와 어긋나지 않는다.
- **신고 실패를 성공처럼 끝내지 않는다.** 실패는 실패로 알린다.
- **좋아요 실패는 정지 계정만 알리고 나머지는 조용히 넘긴다.**
- **셔터는 첫 장에만 있다.** 사진을 한 장 찍으면 그 자리가 "다음" 버튼으로 바뀌고,
  두 번째·세 번째 장은 갤러리에서 고른다. 카메라로 연속 촬영하게 만들고 싶었지만
  원본이 그렇지 않아 그대로 뒀다.
- **집냥이는 위치를 저장하지 않는다.** 지도에도 안 뜨고 피드에만 나온다.
- **사진 규격을 그대로 맞췄다.** 원본 긴 변 1024px / JPEG 50%, 썸네일 200px / 40%.
  같은 서버에 두 앱이 올리므로 여기가 갈라지면 안 된다.
- **썸네일 업로드 실패는 무시한다.** 원본만 올라가면 화면은 그려진다.
- **자르기를 하면 사진의 촬영 위치(EXIF)는 사라진다.** iOS 도 크롭하면서 재인코딩돼
  같은 결과가 된다. 촬영 위치를 쓰려면 자르기를 건너뛰어야 한다.

## 테스트

`bloc_test` 로 50개 (피드 18, 등록 11, 업로드 게이트 5, 지도 8, 자르기 좌표 8).

특히 아래가 실제 버그를 잡는 자리다.

- **추가 페이지 로드가 실패해도 `hasMorePages` 를 안 내린다.** 여기서 false 로 내리면
  일시적인 네트워크 오류 한 번에 페이징이 영구히 막힌다.
- **커서 경계에서 겹쳐 온 게시물은 id 로 걸러낸다.** created_at 이 같은 글이 있으면
  경계에서 중복이 나온다.
- **집냥이로 올리면 좌표가 0 으로, 주소가 null 로 나간다.** 여기가 새면 남의 집
  위치가 지도에 찍힌다.
- **게시물 개수를 못 세면 카메라를 열지 않는다.** 열어주면 30개 제한을 넘겨 올릴 수 있다.
- **지도 조회가 실패해도 이미 찍힌 마커를 지우지 않는다.** 지우면 "여기엔 아무것도
  없다" 로 오해한다.
- **자르기 창은 사진 가운데에서 시작한다.** 이 테스트를 쓰다가 왼쪽 끝에서 시작하던
  버그를 찾았다.

```bash
flutter test
```

## 실행

키는 저장소에 넣지 않는다. 실행할 때 iOS 프로젝트의 `Secrets.swift` 에서 꺼내 넘긴다
(`supabaseURL`, `supabaseAnonKey`, 그리고 주소 검색용 `kakaoRESTApiKey`).

```bash
./run.sh                    # 기기 자동 선택 (iOS / 안드로이드 공통)
./run.sh -d <device-id>     # 기기 지정
SECRETS_PATH=... ./run.sh   # Secrets.swift 위치가 다를 때
```

## 아직 안 한 것

- 안드로이드에서 실행해보지 않았다 (플랫폼 폴더는 있음)
- 옮기지 않은 화면: 둘러보기(주변 시설), 내 정보, 댓글, 칭호 모달, 광고
- 위젯 테스트 없음 — bloc·좌표 계산 테스트만 있다
- 애플 로그인(안드로이드) 미지원 — Supabase 대시보드에 Apple OAuth 설정이 필요하다
- 어댑티브 아이콘은 iOS 아이콘을 기계적으로 줄여 넣은 것이다. 고양이 몸통이 원본에서
  이미 아래가 잘려 있어서, 동그란 런처 마스크 안에서 바닥이 직선으로 보인다.
  제대로 하려면 고양이만 배경 없이 다시 뽑아야 한다
